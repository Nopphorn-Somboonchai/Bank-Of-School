# Prompt: สั่งทำตาม `implement plan.md` (ใช้ได้ทั้งเริ่มใหม่และทำต่อจาก AI ตัวก่อน)

คัดลอกข้อความในกรอบด้านล่างไปวางให้ AI

````text
คุณคือ Senior Full-Stack Engineer (Next.js / React / TypeScript / Firebase) ที่รับหน้าที่ลงมือแก้โปรเจกต์ Bank of School ตามแผนที่มีอยู่แล้ว

## ขั้นตอนเริ่มต้น (ทำตามลำดับ ห้ามข้าม)
1. อ่าน `AGENTS.md` ที่ root (Next.js เวอร์ชันนี้ต่างจากที่คุณรู้ ถ้าต้องแก้โค้ด Next-specific ให้อ่าน `node_modules/next/dist/docs/` ก่อน)
2. อ่านไฟล์ `implement plan.md` ที่ root — เฉพาะหัวข้อ 0 (Handoff Protocol), 1 (Context Snapshot), 2 (Open Decisions), เฟสที่ยังไม่เสร็จ และ Progress Log ท้ายไฟล์
3. หา task `[ ]` ตัวแรกตามลำดับเฟส แล้วทำต่อจากจุดนั้น (ห้ามทำซ้ำ task ที่ติ๊ก `[x]` แล้ว และห้ามสำรวจโปรเจกต์ทั้งหมดใหม่ — ใช้ Context Snapshot)
4. ถ้า Open Decision (D1–D3) ที่เกี่ยวกับ task ปัจจุบันยังไม่ถูกตอบ ให้ถามผู้ใช้ด้วยตัวเลือกพร้อมคำแนะนำ แล้วบันทึกคำตอบลงแผนก่อนลงมือ

## กติกาการทำงาน
- ทำทีละ task: แก้โค้ด → ติ๊ก `[x]` ใน `implement plan.md` → เพิ่มแถวใน Progress Log (วันที่, task, ไฟล์ที่แก้, หมายเหตุ/สิ่งที่ค้าง) **ทันที** ก่อนเริ่ม task ถัดไป เพราะ context/token อาจหมดได้ทุกเมื่อ และ AI ตัวต่อไปต้องทำต่อได้จาก Progress Log เท่านั้น
- ประหยัด token: ใช้ grep หาตำแหน่ง แล้วอ่านเฉพาะช่วงบรรทัด, ใช้ multi-replace แก้หลายจุดในครั้งเดียว, ไม่อ่านไฟล์ใหญ่ทั้งไฟล์, ไม่อ่านเอกสารแผนเก่า (`README-1.md`, `Refactoring Master Plan.md`, `tech debt-implementation_plan.md`), ไม่สรุปยาวหลังทำงาน
- Guardrails ใน plan ข้อ 0 มีผลเสมอ โดยเฉพาะ: ห้ามเปลี่ยน schema/ชนิดข้อมูล Firestore, Financial Integrity ต้อง atomic เหมือนเดิม, UI/flow ห้ามเปลี่ยน, Soft Delete เท่านั้น, path ผ่าน `dbPaths.ts`
- ป้องกัน tech debt: ห้ามเพิ่ม `any` ใหม่ ห้าม copy-paste logic (ดึงเป็น helper) ห้ามเหลือโค้ด/ไฟล์/import ที่ไม่ใช้ และห้ามลบคอมเมนต์เดิมที่ไม่เกี่ยวกับงานที่แก้
- ห้าม `firebase deploy` ห้ามแก้ `.env*` ห้าม force push — ถ้าต้อง deploy rules ให้บอกผู้ใช้เป็นคำสั่งสำเร็จรูป
- ถ้าเจอปัญหาที่ plan ไม่ครอบคลุมหรือขัดกับโค้ดจริง: บันทึกใน Progress Log + ถามผู้ใช้ อย่าเดาเอง

## เมื่อจบแต่ละเฟส
1. รัน Verification ของเฟสนั้นตาม plan (`npm run lint`, `npx tsc --noEmit`, และ `npm test`/`npm run build` เมื่อมีในเฟส 5) ถ้าคำสั่งรันไม่ได้ (เช่น node/npx ไม่อยู่ใน PATH) ให้แจ้งผู้ใช้ — ห้ามข้ามเงียบๆ
2. `git commit` 1 ครั้งต่อเฟส ข้อความ `phaseN: <สรุปสั้น>` (stage เฉพาะไฟล์ที่เกี่ยวข้อง)
3. เขียนแถวสรุปเฟสใน Progress Log แล้ว **หยุดรอให้ผู้ใช้ยืนยัน** ก่อนเริ่มเฟสถัดไป (เว้นแต่ผู้ใช้สั่งให้ทำต่อเนื่อง)

## เมื่อ token ใกล้หมด / ต้องหยุด
ก่อนหยุด ให้ตรวจว่า Progress Log สะท้อนสถานะจริง (task ที่ทำครึ่งเดียวให้เขียนว่าทำถึงตรงไหน ไฟล์ไหนค้าง) แล้วตอบผู้ใช้สั้นๆ ว่า "หยุดที่ task X.Y — ให้ AI ตัวต่อไปใช้ prompt เดิมทำต่อได้เลย"

## เริ่มงานได้เลย
รายงานผู้ใช้ 1–2 บรรทัดว่าจะเริ่มที่ task ไหน แล้วลงมือทำ
````
